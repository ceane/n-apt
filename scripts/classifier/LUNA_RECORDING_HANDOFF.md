# Guarded training-data recording

The native classifier is in a dedicated sidebar section directly below Sources. Its card stacks capture and model controls to fit the sidebar width, keeps capture status at a two-line minimum, shows Ready in green, and pulses the status dot while recording. Start stays disabled unless the backend-active, UI-selected, and expected source IDs agree; the selected real RTL-SDR is RX-only, connected, receiving, and unpaused; source mode is live; display temporal resolution is Lossless; and FFTCanvas has a fresh (3 s maximum age) full frame from that source with matching sample rate, center, FFT configuration, and window. The frame timestamp is rechecked when Start is clicked. No settings are changed automatically.

FFTCanvas copies the complete incoming `currentFrame.iq_data` payload once per accepted sequence. It does not use the FFT display slice. The capture stores one initial applied RX options snapshot, then sparse `PatchOptionsApplied` and `StreamInterrupted` events at byte, sequence, and timestamp boundaries. Each frame contains only epoch/revision, sequence, timestamp, valid sample count, and raw bytes. Frames are never concatenated. Same-sequence callbacks are ignored; a sequence or timestamp gap, epoch/options change, stale/disconnected/background transition, or source change stops recording so no discontinuous samples are presented as contiguous. Labels, channel/morphology observations, tags, and interference markers are in a separate sidecar keyed by capture ID, so they can be attached or revised after capture.

The capture format is `n-apt-native-iq-frames-v1`. It preserves a unique capture session ID and the visualizer session key. The sidebar supports a capture-level signal label, observed N-APT channel (A/B/other/unspecified), bridge/U-dip/coherence, visible-band truncation, pulsing, regular spike spacing, and above-floor spike observations, plus user condition tags (Enter adds, × removes). Those labels export in the separate sidecar; edits during capture are timestamped at the latest frame boundary, and post-capture labels can be revised without changing IQ bytes. Export creates local JSON downloads for the IQ capture and sidecar. Bounds are 3 s without fresh frames, 12 s total, 64 MiB, and 4,000 frames. A 250 ms timer stops collection without requiring another frame callback when data goes stale, and also detects source/mode/status/pause/config changes. Unmount stops an active session. The selected acquisition data is never sent or uploaded by this feature.

Tuning is not disabled. The capture pins its initial acquisition metadata and stops when a received frame reports changed source, epoch, center/sample rate, frame rate, FFT size/window, temporal resolution, or receive status. `PatchOptionsApplied` records the old and new revisions, last old frame and first changed frame sequences/timestamps, byte offset, and changed fields. A same-epoch settings/tuning boundary is represented by that patch only; a source or stream-epoch change also emits `StreamInterrupted` code 1 at the same byte/frame/timestamp boundary because it may represent device reclaim or backend restart. Center-frequency changes are also marked as tune events and shown in the sidebar. The changed-metadata frame is not silently joined into the old capture. The user may start a new capture after the change settles.

Current setup reported by the user: antenna in front of the Mac, cleaner signal reported; RTL-SDR at 3.2 MS/s. The visible page reports 32,768 FFT, 97.66 Hz/bin, rectangular window, and full bin visibility. The Start button was disabled because the live I/Q frame epoch was 30 while the source-list metadata still reported epoch 5, and an additional false guard equated full-payload sample count with analysis FFT size. The frame itself is the current stream authority; capture pins its epoch and stops if a later frame changes epoch. The readiness check now compares full-payload byte/sample consistency independently of FFT length and excludes intentionally sampled pre-start monitor frames from continuity gating. The page now reports Ready and the Start button is enabled. No recording has been started; no backend restart, tune, or acquisition setting change occurred.

Validation after the readiness and sidebar fixes: **4 suites / 99 tests pass** across training capture, panel, sidebar, and FFTCanvas; `npm run typecheck` passes. The running browser confirms the Classifier section is below Sources and Start is enabled. These checks do not prove physical disconnect behavior. The feature was deliberately left idle; no recording was started.

Browser export now feeds the offline `prepare` command through an explicit `browser-capture` manifest format. `prepare` validates the capture contract and emits one timestamped raw-I/Q file per original frame, preserving acquisition-session split, explicit training label, capture annotations, tune events, and metadata-change events; it never merges the time sequence.
